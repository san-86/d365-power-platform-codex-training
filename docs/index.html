Task 1

Inspect the project. Change nothing.

Work in pairs. The Operator uses Codex. The Reviewer checks scope, challenges assumptions and decides whether the plan is safe to approve.

First, clone the repository

Open one bounded workspace

Then, inspect only

Ask Codex to understand first

Paste this prompt. Do not let Codex create or edit anything yet.

Prompt
Inspect this project without changing anything.

Explain:
1. The project purpose and the training task.
2. The important folders and files.
3. Which instructions and source files apply to the onboarding-guide feature.
4. The facts that are established, and the information that is missing or unresolved.
5. A short plan for creating the first section of the guide.

List the files you read or would need to read. Do not create or change files. Wait for my approval before proceeding.
AGENTS.mdProject-wide rules: inspect first, do not invent facts and write only where permitted.
features/onboarding-guide/AGENTS.mdFeature-specific rules and required reading.
Spec.mdThe outcome and scope: create Section 1 only.
Acceptance-criteria.mdThe test for whether the output is good enough.

Task 2

Approve the plan. Build one small change.

Before you continue, the Reviewer must agree that the plan is bounded, supported by the sources and safe to execute.

What to approve

Check the plan before building

  • Does it name the relevant instructions and source files?
  • Is the output limited to Section 1?
  • Does it identify unresolved decisions?
  • Does it say only output/Onboarding-guide.md may change?
  • Does it explain how the result will be checked?
Only after approval

Create Section 1 only

Prompt
Create Section 1 only in output/Onboarding-guide.md.

Use the applicable project instructions, specification, acceptance criteria and approved source material. Do not change files outside output/.

Before completion:
1. List every file changed.
2. Validate the deliverable against each acceptance criterion.
3. Flag unsupported claims, missing decisions or information that still requires human input.

Stop when information is missing.

Do not invent a named escalation contact, a mailbox, a service-level response time or a system behaviour that the project sources do not prove.

Flag the gap.

Validation

Check the deliverable, not the completion message.

Open output/Onboarding-guide.md and compare it with the acceptance criteria. Click each item as you verify it. Your progress is stored only in this browser.
