# Project instructions

## General behaviour

- This is a synthetic training project. Treat all content as fictional.
- Inspect relevant files before proposing or making changes.
- Do not invent product behaviour, business rules, owners, escalation routes, URLs or policy content.
- State missing information and unresolved decisions explicitly.
- Propose a short plan before substantial changes and wait for human approval.
- Work in small, reviewable increments.
- Do not change files outside `output/` unless the human explicitly approves it.
- Report every file changed and any validation performed.
- Validate the output against the feature acceptance criteria before declaring the task complete.

## Feature routing

When working on `features/onboarding-guide`:

1. Read `features/onboarding-guide/AGENTS.md`.
2. Read `features/onboarding-guide/Spec.md` and `Acceptance-criteria.md`.
3. Read `features/onboarding-guide/Workflow.md` before describing or changing the support process.
4. Use only the authoritative information in `source-material/`, `policies/` and `Decisions.md`.

## Write boundary

For the training exercise, create or edit only files below `output/`.
